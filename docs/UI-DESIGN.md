## 2. 设计原则

1. **操作页是主战场**：进入 App 默认停在「操作」，其它页面都是辅助信息，切走再切回不打断接收与 QSO。
2. **发射永远可中断**：任何自动发射都必须有可见的「停止发射」入口与防误发确认，自动应答（Call 1st）也不例外。
3. **信息密度分层**：默认只显示决策必需的信息（呼号、报告、状态标记），原始参数与低频操作用折叠区承载。
4. **一切可解释**：每个可调参数都要有单位、范围与「调大/调小会怎样」的一句话说明。
5. **离线优先**：网格图与全部统计完全本地计算，不依赖网络；ADIF 走系统文件选择器。
6. **不降级工具链**：沿用现有 AGP 9.3.2 / Gradle 9.5.0 / Kotlin 2.2.10 / JDK 25。

## 3. 信息架构与导航

### 3.1 导航结构

```
┌──────────────────────────────────────────────────────┐
│                    内容区（随 Tab 切换）               │
│                                                      │
├──────────────────────────────────────────────────────┤
│  ⌂ 操作      ☰ 日志      ◉ 网格      ⚙ 设置          │
└──────────────────────────────────────────────────────┘
```

- 组件：Material3 `NavigationBar` + `NavigationBarItem`；图标用 material-icons-core 内置集（`Home` / `List` / `Place` / `Settings`），**不引入** `material-icons-extended`（体积大）。
- 状态提升到 `MainActivity` 的 `rememberSaveable`，切换 Tab 不重建 ViewModel，接收与 QSO 持续运行。
- 「停止接收」在 `onStop` 才触发（保持现状），切 Tab 不触发。

### 3.2 各页职责边界

| 页面 | 职责 | 不负责 |
| --- | --- | --- |
| 操作 | 瀑布、解码列表、选频、QSO 发射与自动序列、本次会话的实时状态 | 长期统计数据、参数持久化 |
| 日志 | 通联记录的查询/筛选/编辑/删除、ADIF 导入导出、统计仪表盘 | 实时解码、发射 |
| 网格 | 已通联/已确认网格的可视化与进度、点击网格看该网格的通联 | 单条记录的编辑（跳日志页处理） |
| 设置 | 台站身份、解码参数、发射策略、音频、日志与 ADIF、关于 | 实时操作 |

### 3.3 跨页数据流

```
DataStore(设置) ──┐
                  ├─→ SessionViewModel ──→ 操作页
Room(通联日志) ───┤         │
                  │         └─→ 新增一条通联（QSO 完成时）
                  ├─→ LogViewModel ──────→ 日志页
                  └─→ GridViewModel ─────→ 网格页（网格索引用于高亮）
```

- 网格索引（已通联/已确认网格集合）在日志变更后增量刷新，供**操作页颜色高亮**与**网格页着色**共用。

**组件与交互**

| 组件 | 行为 |
| --- | --- |
| 身份行 | 只读显示呼号/网格，点击跳设置页 |
| 时隙进度 | 进度条 + 奇偶 chip + 丢帧数（>0 变红） |
| 瀑布 | 点击选频；双指缩放/拖动改频率范围（可选，7c 后再做）；右上角小按钮切高度档 |
| 频率微调 | 步进值在设置里可配（默认 10 Hz），长按连续调整 |
| Hold Tx Freq | 开：应答不跟随对方频率；关：应答时 TX 频率=对方 DF |
| 过滤条 | `CQ only` 只影响列表显示；`排除已通联` 依据 Room 索引；搜索框支持呼号或前缀（逗号分隔多个） |
| 解码行 | 点击=选频（并同步 TX 频率）；右侧「应答」按钮=进入应答流程（防误发确认）；**长按**=打开逐条发送菜单 |
| 逐条发送菜单 | 应答 / 发信号报告（用该条 SNR）/ 发 R+报告 / 发 RR73 / 发 73 / 发送自由文本；选中后设为**下一时隙的一次性发射**，发完自动回空闲 |
| 折叠面板 | 折叠态一行摘要；展开态含周期、Hold Tx、Call 1st 与三个主按钮 |

**颜色高亮判定顺序**（从高到低）

1. 是否为当前 QSO 对手 → 琥珀；
2. 是否发给我（`to == myCall`）→ 亮蓝，加粗；
3. 网格是否未通联 → 绿点；前缀是否未通联（DXCC 近似）→ 红点；
4. 其余默认。

└────────────────────────────────────────────────────┘

**渲染方案**

- 投影：等距圆柱（`x = (lon+180)/360·W`，`y = (90−lat)/180·H`）。
- Maidenhead 层级：`field`（AA–RR，18×18，20°×10°）→ `square`（数字 0–9，2°×1°）→ `subsquare`（A–X，5′×2.5′，本期只显示到 square）。
- 底图：**先只画经纬网与赤道/本初子午线**；是否内嵌简化海岸线（约 100 KB 级 GeoJSON）作为可选项，代码预留 `BaseMapLayer` 接口，后续可无痛替换。
- 缩放：`detectTransformGestures` 做平移/缩放；缩放到阈值自动切换 field↔square 着色粒度。
- 着色数据来自 Room 的网格索引；「已确认」取 `QSL_RCVD='Y'` 或 `LOTW_QSL_RCVD='Y'`。
- 点击网格：底部浮层列出该网格的通联，点单条跳日志页编辑。

**统计区**：已通联/已确认的 field 与 square 计数、完成度进度条。DXCC 统计延后（需精确实体表）。

| 频率过采样 `freqOsr` | 1 | 2 | 4 |
| 最低同步分 `minScore` | 12 | 10 | 8 |
| LDPC 迭代 `ldpcIters` | 10 | 25 | 50 |
| 最大候选 `maxCandidates` | 80 | 140 | 250 |
| 最大解码 `maxDecoded` | 30 | 50 | 80 |
| 分析频段 `fMin/fMax` | 200–3000 | 200–3000 | 200–3000 |

> 频率范围不随预设变化，只由高级设置控制；宽频段（如 200–3500）会显著增加候选数与耗时。

**关键约束**

- `fMin/fMax/timeOsr/freqOsr` 属于 `monitor_config_t`，**改动需要重建引擎**（停采集 → 重新 initialize → 重新开始采集），设置页要提示「立即生效将重启接收」。
- `minScore/ldpcIters/maxCandidates/maxDecoded` 是每次解码读取的参数，**热生效**，无需重启。
- 所有设置写入 DataStore，App 启动时加载；「台站」变更立即同步到 `SessionViewModel`。

## 6. 关键交互流程

### 6.1 手工完成一次通联

```
点解码行[CQ]「应答」→ 防误发确认 → 进入 RESPONDER
  → 发「<对方> <我> <网格>」
  → 收对方报告 → 发「R<我测得的报告>」
  → 收 RR73 → 发 73 → 完成 → 写入 Room → 日志页可见 & 网格点亮
```

### 6.2 Call 1st 自动应答

```
设置选「最强 CQ」或「首个 CQ」→ 操作页显示 Call 1st 徽标
每个接收时隙结束：
  若 QSO 空闲
  且存在满足「过滤 + 排除已通联 + 非自己 + 非当前对手」的 CQ
  → 自动锁定最强/首个 → 进入 RESPONDER → 按时隙发射
QSO 完成或失败 → 自动解除 armed，回到空闲（不会连续自动叫人）
```

> 首次启用 Call 1st 必须过一次防误发确认；QSO 结束后需再次手动开始，避免无限自动呼叫。

### 6.3 逐条手动发送

```
长按解码行 → 菜单选一项 → 生成文本 → 设为「一次性发射」
下一发射时隙发出 → 发出后清空，不进入自动序列
```

### 6.4 过滤与排除

- `CQ only`、`排除已通联`、呼号/前缀搜索三者是**显示过滤**，不丢弃解码结果；
- `排除已通联` 与 Call 1st 共用同一份判定逻辑（Room 索引 + 进行中的 QSO），避免一个过滤另一个不过滤。

## 9. 待确认与风险

| 项 | 说明 |
| --- | --- |
| 已确认状态的来源 | 本阶段只认 ADIF 导入的 `QSL_RCVD` / `LOTW_QSL_RCVD`；App 内不提供在线 QSL 查询 |
