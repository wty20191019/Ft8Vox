7a 相对本文档的两处偏差（有意为之，此处备案）：

1. **波段选择器同时出现在操作页**：本文档原定波段只在设置页。实际在操作页顶部也加了一个紧凑的波段下拉——
   切换波段是操作中的高频动作，藏在设置里不合用。两处写的是同一份 DataStore 值，不会出现不一致。
2. **ADIF 导入导出在日志页与设置页都可用**：共用同一个 `AdifActionRow` 组件，符合本文档第 5.2 / 5.4 节的描述。

7a 落地时发现的约束（已记入 `docs/ROADMAP.md` 阶段 7 进展）：

- AGP 9 内置 Kotlin 编译，KSP 需要 `android.disallowKotlinSourceSets=false` 才能注册生成代码目录。
- ADIF 的长度字段是 **UTF-8 字节数**，不是字符数；中文备注必须按字节解析/生成。
- SAF 导出若用 `text/plain`，文件名会被追加 `.txt`；应使用 `application/octet-stream` 保留 `.adi`。
- 打开 SAF 会让 Activity 进后台并触发 `onStop` → 停止接收（阶段 9 上前台服务后解决）。

7c / 7d 落地时相对本文档的偏差（有意为之，此处备案）：

1. **网格地图为固定 2:1 视口**：等距圆柱投影的世界是 360°×180°（2:1）。地图区按 `aspectRatio(2f)` 布置，
   默认「适应窗口」正好铺满、无拉伸也不留白（先试过 `weight(1f)` 填满视口，但竖屏下会裁掉大量经度，
   同屏看不全已通联网格，故回退为 2:1 全球视图）。
2. **无海岸线底图**：仅绘制 Maidenhead 场/方格线、赤道与本初子午线；`BaseMapLayer` 为后续海岸线/地形预留。
3. **新前缀为紧凑近似**：`CallPrefix` 取「首个数字前连续字母段」（`JA1ABC`→`JA`、`KD9XYZ`→`KD`），
   不是精确 DXCC 前缀表（本阶段明确不做精确 DXCC）。
4. **实时台站窗口固定 15 分钟**：`SpotBuilder.DEFAULT_WINDOW_MS`，同呼号取最近一条；会话内解码缓存即数据源，不落库。
5. **网格页应答走确认弹窗 + 录音权限链路**：与操作页一致，先弹确认再申请权限，避免误发。
6. **实时点无法在模拟器验证**：模拟器无天线/无音频输入，`实时 N 台` 恒为 0；绘制与命中逻辑由 JVM 单测覆盖，
   真机端到端回归放到 7e。

7b 落地时相对本文档 §5.4 的偏差（有意为之，此处备案）：

1. **设置页为平铺分区，不做可折叠面板**：与 7a 既有的设置页样式保持一致；顺序为 台站 → 发射 → 解码 → 音频 → 日志与 ADIF → 关于
   （与本文档 §5.4 的「解码参数在发射之前」略有出入）。
2. **高级参数用「−/值/+」步进行**，而非文本输入：避免软键盘与非法输入，步长按字段区分（OSR 1、得分 1、LDPC 5、候选 20、解码 5、频率 50 Hz）。
3. **新增「自定义」预设档**：手动改任一项高级参数后，预设高亮切到 `DecodePreset.CUSTOM`，不会假装仍等于某个预设。
   （枚举按名字持久化，新增档位不影响旧数据。）
4. **未提供 `getDecodeParams` 回读接口**：native 侧只做单向下发 + 内部钳制；回读由 Kotlin 侧 `DecodeParams` 保存。
5. **「频率范围需重启」未做一键重启**：设置页只以文案提示，用户自行停止/开始接收。

7e 收尾落地时相对本文档 §5.4 的偏差（有意为之，此处备案）：

1. **设置页新增「界面」区**：把原本只有代码、没有入口的瀑布高度档位（紧凑/标准/高）补上 UI；顺序为 台站 → 发射 → 解码 → 界面 → 音频 → 日志与 ADIF → 关于。
2. **「备注」明确为「新通联默认 COMMENT」**：台站备注在 QSO 自动落库时写入该记录的 `COMMENT`（记录时快照，可留空）；再由工具追加自动备注 `Distance: 1738 km, QSO by Ft8Vox`（仿 FT8CN）——距离按我的网格 ↔ 对方网格的**大圆距离**取整到 km；任一方缺网格时只留 `QSO by Ft8Vox`；有台站备注时为 `台站备注, Distance: …`。字段说明文案已标注。
3. **补「恢复默认（保留台站信息）」按钮**：调用既有的 `SettingsViewModel.resetToDefaults()`，保留呼号/网格/备注，其余回落默认。
4. **「默认发射周期」同时出现在设置页**：操作页仍可临时切换，设置页作为持久默认值。
5. **呼号/网格加错误态**：呼号留空、网格非法（非 2/4/6/8 位合法 Maidenhead）时输入框报红并给出提示。
6. **操作页解码列表补空态**：区分「未开始接收 / 已接收但本时隙无解码 / 被过滤」，由纯函数 `decodeEmptyHint` 生成（JVM 单测覆盖）。
7. **真机全流程回归清单独立成文**：见 `docs/REGRESSION.md`；实时台站点等无法在模拟器验证的项列入真机回归。

## 2. 设计原则

1. **操作页是主战场**：进入 App 默认停在「操作」，其它页面都是辅助信息，切走再切回不打断接收与 QSO。
2. **发射永远可中断**：任何自动发射都必须有可见的「停止发射」入口与防误发确认，自动应答（Call 1st）也不例外。
3. **信息密度分层**：默认只显示决策必需的信息（呼号、报告、状态标记），原始参数与低频操作用折叠区承载。
4. **一切可解释**：每个可调参数都要有单位、范围与「调大/调小会怎样」的一句话说明。
5. **离线优先**：网格图与全部统计完全本地计算，不依赖网络；ADIF 走系统文件选择器。
6. **不降级工具链**：沿用现有 AGP 9.3.2 / Gradle 9.5.0 / Kotlin 2.2.10 / JDK 25。

## 3. 信息架构与导航

### 3.1 导航结构

```
┌──────────────────────────────────────────────────────┐
│                    内容区（随 Tab 切换）               │
│                                                      │
├──────────────────────────────────────────────────────┤
│  ⌂ 操作      ☰ 日志      ◉ 网格      ⚙ 设置          │
└──────────────────────────────────────────────────────┘
```

- 组件：Material3 `NavigationBar` + `NavigationBarItem`；图标用 material-icons-core 内置集（`Home` / `List` / `Place` / `Settings`），**不引入** `material-icons-extended`（体积大）。
- 状态提升到 `MainActivity` 的 `rememberSaveable`，切换 Tab 不重建 ViewModel，接收与 QSO 持续运行。
- 「停止接收」在 `onStop` 才触发（保持现状），切 Tab 不触发。

### 3.2 各页职责边界

| 页面 | 职责 | 不负责 |
| --- | --- | --- |
| 操作 | 瀑布、解码列表、选频、QSO 发射与自动序列、本次会话的实时状态 | 长期统计数据、参数持久化 |
| 日志 | 通联记录的查询/筛选/编辑/删除、ADIF 导入导出、统计仪表盘 | 实时解码、发射 |
| 网格 | 网格地图（历史 已通联/已确认 着色 + **本会话实时接收台站点与信号**）、进度与统计、点击查看 | 单条记录的编辑（跳日志页处理） |
| 设置 | 台站身份、解码参数、发射策略、音频、日志与 ADIF、关于 | 实时操作 |

### 3.3 跨页数据流

```
DataStore(设置) ──┐
                  ├─→ SessionViewModel ──→ 操作页
Room(通联日志) ───┤         │
                  │         ├─→ 新增一条通联（QSO 完成时）
                  │         ├─→ 已通联索引（呼号/网格）供操作页过滤与高亮
                  │         └─→ 本会话解码 ──→ 网格页实时台站点
                  ├─→ LogViewModel ──────→ 日志页
                  └─→ 日志网格索引 ──────→ 网格页历史底图
```

- 已通联索引（呼号/网格集合）在日志变更后刷新，供**操作页「排除已通联」与颜色高亮**、**网格页历史着色**、**Call 1st 过滤**共用。
- 网格页的实时层直接消费 `SessionViewModel.messages`（本会话解码），不额外落库；历史层消费 Room。

## 5. 页面详设

### 5.1 操作页（Operate）—— JTDX / FT8CN 经典分区

把 JTDX 的「Band Activity + Rx/Tx 频率面板」压缩为手机上的竖向分区：

```
┌────────────────────────────────────────────────────┐
│ F4FSY / JN25   20m ▾   ● 接收中        [停止接收]  │  ← 身份 + 波段 + 运行态
├────────────────────────────────────────────────────┤
│ 时隙 ████████░░░░  奇数周期   丢帧 0   已解 12     │  ← 时隙进度 + 统计
├────────────────────────────────────────────────────┤
│                                                    │
│                 瀑  布  区（高度三档可调）          │
│          ▽ 红线 = TX   ▽ 绿线 = RX                 │
│                                                    │
├────────────────────────────────────────────────────┤
│  200 Hz            1603 Hz            3006 Hz       │  ← 频率轴
├────────────────────────────────────────────────────┤
│ RX  1521 Hz    点解码行 / 瀑布设置                  │  ← Rx / Tx 频率面板
│ TX  1000 Hz    [−100][−10][+10][+100]   Hold Tx ☐  │
├────────────────────────────────────────────────────┤
│ [CQ only] [排除已通联]  🔍 呼号/前缀     显示 12    │  ← 过滤条
├────────────────────────────────────────────────────┤
│ 12:03:15 −08 DT+0.1 1521 ▎● CQ JA1ABC PM95        │  ← 解码列表（占满剩余）
│ 12:03:15 −12 DT−0.2  980 ▎  F4FSY JA1ABC −05      │
│ ▎=发给我的  ●=新网格/新前缀                         │
│ ...                                                │
├────────────────────────────────────────────────────┤
│ QSO 空闲       Call 1st 关      [停止发射]  [展开] │  ← 折叠式控制面板
└────────────────────────────────────────────────────┘
```

**Rx / Tx 与 Hold Tx Freq**

- **RX**：点解码行或瀑布设置的「收听/应答频率」，对应瀑布**绿线**。
- **TX**：我方发射频率，对应瀑布**红线**，由 `−100 / −10 / +10 / +100`（步进值后续可配）微调。
- **Hold Tx Freq** 开：点解码行只改 RX，TX 保持不动（split / 堆叠场景）；
  关：点解码行同时把 TX 跟到 RX（普通使用「点谁打谁」）。**默认关**。
- 应答时文本为 `<对方> <我> <报告|网格>`，频率取 TX；若 Hold Tx 关且该条解码带 DF，则先把 TX 同步到 RX。

**组件与交互**

| 组件 | 行为 |
| --- | --- |
| 身份行 | 只读显示呼号/网格，点击跳设置页；波段下拉（无 CAT，人工指定） |
| 时隙进度 | 进度条 + 奇偶 chip + 丢帧/已解时隙数（丢帧 >0 变红） |
| 瀑布 | 点击选频（设 RX，按 Hold Tx 决定是否同步 TX）；右上角小按钮切高度档 |
| Rx/Tx 面板 | RX 只读 + TX 步进微调 + Hold Tx 开关；长按步进可连续调整 |
| 过滤条 | `CQ only` / `排除已通联` / 呼号前缀搜索，均为**显示过滤**，不丢弃解码结果 |
| 解码行 | **点击**=设 RX（按 Hold Tx 同步 TX）；**长按**=逐条发送菜单；行尾「应答」=进入对应答流程（防误发确认） |
| 折叠面板 | 折叠态一行摘要；展开态含周期、Hold Tx、Call 1st 与主按钮 |

**解码行高亮判定顺序**（从高到低）

1. 是否为当前 QSO 对手 → 琥珀色左条 + 行底色 8%；
2. 是否发给我（`to == myCall`）→ 亮蓝粗左条 + 加粗；
3. 网格是否未通联 → 绿点 ●；前缀是否未通联（紧凑前缀近似，非精确 DXCC）→ 红点 ●；
4. 其余（含已通联）→ 默认灰。

行内固定列：`HH:MM:SS  SNR  DT  DF  左条  标记  报文文本`，等宽字体列对齐。

**逐条手动发送**（长按解码行；仅 QSO 空闲时可用）

```
应答 | 发报告（用该条 SNR） | 发 R 报告 | 发 RR73 | 发 73 | 自由文本…
```

选中项设为「下一发射时隙的**一次性发射**」，发完自动解除武装回到空闲，不进入自动序列、不改变 QSO 状态机。

**Call 1st（自动应答）**

- 折叠面板内三态：**关 / 最强 CQ / 首个 CQ**；首次启用需过一次防误发确认。
- 每个接收时隙结束、QSO 空闲时，从本时隙解码中挑一个满足「显示过滤 + 非自己 + 非已通联 + 是 CQ」的台站自动进入应答。
- QSO 完成或失败后**自动解除**，不会连续自动呼叫；需要再次手动开启。

### 5.3 网格页（Grid）—— 实时台站 + 历史底图

像 FT8CN 的网格图 / GridTracker2 的实时地图那样，把**历史已通联网格**与**本会话实时接收到的台站**画在同一张离线地图上：

```
│ [大网格 | 小网格]  [实时 ☑]  [适应窗口]            │
├────────────────────────────────────────────────────┤
│                                                    │
│            Canvas 自绘 Maidenhead 网格图           │
│                                                    │
│   · 底图：已通联(绿) / 已确认(蓝) 方格             │
│   · 实时：本会话台站按网格中心投点                 │
│           颜色 = 高亮分类，半径/亮度 = SNR          │
│           点旁标呼号；⊕ = 我方台站                 │
│   · 双指缩放 / 单指拖动平移 / 点击选取             │
│                                                    │
├────────────────────────────────────────────────────┤
│ 选中：JA1ABC  PM95  −05 dB  DT +0.1  1521 Hz 12:03 │
│ [应答]  [在日志中查看]                             │
└────────────────────────────────────────────────────┘
```

**渲染方案**

- 投影：等距圆柱（`x = (lon+180)/360·W`，`y = (90−lat)/180·H`），视口 = 世界坐标经缩放/平移，纯函数 `MapProjection`（可 JVM 单测）。
- Maidenhead 层级：`field`（AA–RR，18×18，20°×10°）→ `square`（数字 0–9，2°×1°）→ `subsquare`（A–X，5′×2.5′）。
  本期只画到 **field / square**，用顶部开关切换粒度。
- 底图 `BaseMapLayer`：默认画 Maidenhead 网格线 + 经纬网（赤道/本初子午线加粗）；
  简化海岸线作为后续可插拔层预留接口，本期**不内嵌**。
- 历史着色来自 Room 网格索引：已通联 `#66BB6A`（60% 填充）、已确认 `#1E88E5`（80% 填充）、未通联浅灰描边。
- **实时层（本轮新增）**：
  - 数据来源 = 本会话 `SessionViewModel.messages` + 日志里的「呼号→网格」缓存；
  - 每条解码解析出呼号与网格，构造 `Spot(call, grid, snr, dt, df, utcMs, highlight)`；
  - 同呼号取最近一次；默认只显示最近 **15 分钟**（窗口可配）；
  - 点落在网格中心；颜色复用操作页高亮规则（当前对手 / 发给我 / 新网格 / 新前缀 / 已通联）；
  - **信号呈现**：半径随 SNR 增大、透明度随「变旧」衰减，点旁标注呼号；底部图例说明颜色与大小含义。
- 点击：命中实时点 → 显示台站详情（呼号/网格/SNR/DT/DF/时间）与「应答」；命中空格子 → 列出该网格的历史通联。

**统计区**：已通联/已确认的 field 与 square 计数、完成度进度条（复用 `LogQuery.computeStats`）。DXCC 统计延后（需精确实体表）。

**已知取舍**

- 模拟器无天线信号，实时点需靠「文件注入 / 自回环」或真机验证；无网格的报文用日志缓存补全，仍无则不上图（详情提示「网格未知」）。
- 海岸线底图不在本期；地图可辨识度靠 Maidenhead 网格线与已成形的斑点分布。

**解码参数三档预设**（写入 native 的值）

| 参数 | 快 | 标准（默认） | 深 |
| --- | --- | --- | --- |
| 时间过采样 `timeOsr` | 1 | 2 | 4 |
| 频率过采样 `freqOsr` | 1 | 2 | 4 |

**关键约束**

- `fMin/fMax/timeOsr/freqOsr` 属于 `monitor_config_t`，**改动需要重建引擎**（停采集 → 重新 initialize → 重新开始采集）；设置页以文案提示「需重启接收生效」，未做一键重启。
- `minScore/ldpcIters/maxCandidates/maxDecoded` 是每次解码读取的参数，**热生效**：设置一变即经 `SessionViewModel.applyDecodeParams()` → `AudioEngine.setDecodeParams()` 下发 native，无需重启。
- 所有设置写入 DataStore，App 启动时加载；「台站」变更立即同步到 `SessionViewModel`；设置页读出的解码参数会经 `DecodeSettings.clamped()` 钳制。

## 6. 关键交互流程

### 6.1 手工完成一次通联

```
点解码行[CQ]「应答」→ 防误发确认 → 进入 RESPONDER
  → 发「<对方> <我> <网格>」
  → 收对方报告 → 发「R<我测得的报告>」
  → 收 RR73 → 发 73 → 完成 → 写入 Room → 日志页可见 & 网格点亮
```

### 6.2 Call 1st 自动应答

```
设置选「最强 CQ」或「首个 CQ」→ 操作页显示 Call 1st 徽标
每个接收时隙结束：
  若 QSO 空闲
  且存在满足「过滤 + 排除已通联 + 非自己 + 非当前对手」的 CQ
  → 自动锁定最强/首个 → 进入 RESPONDER → 按时隙发射
QSO 完成或失败 → 自动解除 armed，回到空闲（不会连续自动叫人）
```

> 首次启用 Call 1st 必须过一次防误发确认；QSO 结束后需再次手动开始，避免无限自动呼叫。

### 6.3 逐条手动发送

```
长按解码行 → 菜单选一项 → 生成文本 → 设为「一次性发射」
下一发射时隙发出 → 发出后清空，不进入自动序列
```

### 6.4 过滤与排除

- `CQ only`、`排除已通联`、呼号/前缀搜索三者是**显示过滤**，不丢弃解码结果；
- `排除已通联` 与 Call 1st 共用同一份判定逻辑（Room 索引 + 进行中的 QSO），避免一个过滤另一个不过滤。
