# Ft8Vox · 使用与设计（唯一文档）

> Ft8Vox 把 Android 手机变成一台 FT8 / FT4 终端：采集电台音频实时解码，手动或自动完成通联并落库。
> 手机**强制竖屏**；音频 I/O 用 **AAudio**；DSP 在 native 层复用开源的 **ft8_lib**（含 kissfft）；
> 界面用 **Jetpack Compose**（Material 3）。**无 CAT**：不控制电台频率 / 模式 / PTT，发射靠电台 **VOX**
> 或手动 PTT。音频接入支持**声学耦合**与 **USB 声卡 / OTG**。
>
> 对标基准是 FT8CN（BG7YOZ / N0BOY，Android / Java）；凡与 FT8CN 不一致处一律在 [§8](#8-与-ft8cn-的偏离清单) 列出。
> 许可 **GPL-3.0**。
>
> **本文是 Ft8Vox 的唯一文档，只描述当前实现**；构建、运行与目录结构见 [README](../README.md)。

## 1. 功能与范围

### 1.1 做什么

| 能力 | 说明 |
| --- | --- |
| **接收** | 采集电台音频 → 实时解码，显示瀑布图与解码报文列表（时隙 / UTC / SNR / dT / 报文 / 音频频率 / 国家 / 距离）。 |
| **发射** | 手动（CQ 及 `CQ DX` 等前缀 / 应答 / 报告 / R 报告 / RR73 / 73 / 自定义报文）或**自动程序**（自动选台、自动跑完整段 QSO）。 |
| **QSO 自动系统** | 六步报文序号状态机 + 单档常开自动程序 + 两个安全阀（发射监管、无回应兜底）。 |
| **日志** | 通联自动落库（含 `Distance: … km, QSO by Ft8Vox` 备注），ADIF **合并**导入 / 导出。 |
| **地图** | 离线世界卫星底图 + 网格 / 呼号 / CQ 旗 / 信号连线 / 昼夜灰线。 |
| **跟踪 CQ 列表** | 手动或自动收录的呼号名单，是自动程序呼叫 CQ 的例外名单。 |

### 1.2 明确不做

- **CAT / 电台控制**：不自动控制频率、模式或 PTT（靠 VOX 或手动 PTT）。
- **在线服务**：在线地图瓦片、在线日志（CloudLog / LoTW / eQSL）、局域网 Web 后台。
- **竞赛与特殊模式**：Hound / Fox、FST4 等其它协议、竞赛报文、`TU;` 变体。
- **自动程序档位**：AutoSeq 等级 / AutoMode / `paused` / 启用确认框 / `retryLimit` 重试体系。
- **选台分级**：不按 DX / 区域 / SNR / 距离加权（照 FT8CN 只按解码先后）。
- **精确 DXCC 分级**：实体识别用呼号前缀映射表（近似），不做逐条精确判定。
- **显示层自定义**：瀑布配色切换、接收频率自动窄带过滤、解码列表筛选与搜索。
- **外观档位**：亮 / 暗主题切换、字体档位（界面固定深色 + 固定字号）。

## 2. 快速上手

### 2.1 30 秒

| 步骤 | 做什么 | 去哪 |
| --- | --- | --- |
| 1 | 填**呼号**与**网格**，选**波段与频率** | 设置 → 台站 |
| 2 | 选输入 / 输出设备，调**输入增益** | 设置 → 音频 / 电台 |
| 3 | 回操作页，点解码列表中间的提示授权麦克风，之后自动开始接收 | 操作 |
| 4 | 点 CQ 报文 → 左滑「呼叫」（或在解码行长按菜单里选「呼叫」），再打开信息头第 1 行右侧的**「发送总开关」** | 操作 |
| 5 | 通联完成后自动写入日志；可导出 ADIF | 日志 |

> **发射的唯一闸门是「发送总开关」**（默认关＝只接收）。本应用**没有**「确认发射」弹窗，点下即排程；
> 打开总开关前请先确认电台已就绪。

### 2.2 硬件接线与前期准备

- **声学耦合**：手机麦克风对着电台喇叭（收），手机喇叭对着电台话筒（发）。最简单，但受环境噪声影响。
- **USB 声卡 / OTG**：手机 USB 接声卡，声卡接电台 data 口；设置页的输入 / 输出设备选对应声卡（不是「系统默认」）。
- **电台侧**：无 CAT，发射靠 **VOX** 或手动 PTT。调 VOX 灵敏度到「只有 FT8 音频能触发」；必要时在设置页开**发射前导音**让 VOX 抢先键控。
- **时间**：FT8 依赖精确对时，手机时间误差应小于约 1 s。保持「自动设置时间」开启；若解码 DT 长期偏大，用时隙偏移校准（见 [§3.6](#36-设置页)）。

## 3. 界面（手机竖屏）

### 3.1 骨架与信息头

界面固定竖屏，自上而下：**信息头（四行，全局常驻）→ 页面内容 → 底部导航**。

```
┌──────────────────────────────────┐
│ 14.074 000    20m·FT8   [总开关 关]│ ① 信息头 第1行
│ 11:56:08  时隙 ▓▓▓░░ 1  [TX0] -45dB ●│ ②      第2行
│ BG7ZZZ OM89            解码118ms  DX→JA1ABC PM95 -15│ ③      第3行
│ 解码12/min 总123 QSO7 队列0   时间同步 29.09.2026│ ④      第4行
├──────────────────────────────────┤
│ [监听] [清除] [跟踪 3]  时间同步 │ ⑤ 控制行（操作页）
├──────────────────────────────────┤
│ 11:56:00  -12  0.1  CQ JA1ABC PM95 │ ⑥ 页面内容
│ 1512 Hz  JA  1234 km              │
│ …                                │
├──────────────────────────────────┤
│ ▭操作  ▭频谱  ▭地图  ▭日志  ▭设置│ 底部导航
└──────────────────────────────────┘
```

**信息头四行**（全局常驻，任何页面都在）：

| 行 | 左 | 中 | 右 |
| --- | --- | --- | --- |
| 1 | 大频率 `14.074 000` + `20m·FT8` | — | **发送总开关**（方块，开=绿底） |
| 2 | 时钟 `11:56:08` | 时隙进度条 + `时隙 N` | 输入电平 + `TX0`/`TX1` + 收发状态点 |
| 3 | 我方 `呼号 网格` | `解码 nms` | `DX→ 呼号 网格 报告` |
| 4 | `解码n/min · 总n · QSOn · 队列n` | — | `时间同步`（或红字`时间不同步`）+ 日期 |

- 频率 = 设置里的刻度频率；波段 / 模式同源。
- `TX0`/`TX1` 是**我方发射时隙**的奇偶：轮到我方或正在发射时**红底黑字**，其余深灰底灰字。
- DX 栏：有目标显示 `DX→ 呼号 网格 报告`；没目标但正在叫 CQ 时显示绿字 `CQ 呼叫中，暂无目标`；其余 `DX→ 未设目标`。
- 未设置呼号时第 3 行变红：`请先到设置填写呼号与网格`。
- **发送总开关**始终可见、始终可点；关=「只接收」，开=「允许发射」。

**底部导航** 5 项（`图标 + 文字`，选中项绿色）：**操作 / 频谱 / 地图 / 日志 / 设置**。
「频谱」图标是自绘的 4 条横向瀑布色带 + 一条红色发射线，其余用 Material 图标。

### 3.2 操作页

**控制行**：`[监听] [清除] [跟踪 N]` + 右侧时间同步提示。

- **监听**：开始 / 停止接收。
- **清除**：清空解码列表。
- **跟踪 N**：打开「跟踪 CQ 列表」（N＝名单人数）。
- 操作页**没有**筛选与搜索，解码列表永远显示全部（仍受忽略名单与「已通联」呈现影响）。

**解码列表**（主体，尽量多行）：两行制、整行底色高亮、自动吸顶到最新，详见 [§4](#4-解码与显示)。

**发射区**（底部常驻，三块）：

1. `[自定义报文 ______] [CQ 前缀 无 ▾] [发送]`
   - 框平时**保持空白**，用灰字占位**回显当前待发报文**；点「发送」把框里内容排到下一个（或最近可发的）我方时隙，**QSO 进行中也照发**（插一条、不打断原序列）；排程成功后框清空。
   - **自定义框为空时「发送」置灰**。
   - `[CQ 前缀 ▾]` 打开 **CQ 前缀弹窗**（8 个可编辑格子，点一行即选中，见 [§5.3](#53-自定义报文与-cq-前缀)）。
2. `[停止发射] [自动程序] 正在发送：<报文>`
   - 「停止发射」红色，仅在发射中可用。
   - 「自动程序」打开自动程序弹窗。
   - 发射中**红字**显示本时隙**实际在播**的那条报文；空闲时**灰字**显示「空闲」。
3. **六个报文槽 3 列 × 2 行、列优先**：

   ```
   1 网格    3 R报告    5 73
   2 报告    4 RR73     6 CQ
   ```

   槽号就是六步序列的序号；**点哪一格就发那一格的报文**（CQ 槽走「呼叫 CQ」）。槽内容每帧现算，不持久化。
   指示：**正在播的那格红点红边、待发那格绿点绿边**（按报文序号判定，红优先于绿）。

其它行为：

- **返回键**：接收中退到后台**继续接收**（前台服务保活）；弹窗打开时先关弹窗。
- 导出的日志 / 手动新增编辑在「日志」页；**手动输入 DX 呼号 / 网格 + 呼叫**在设置页「台站」组，不占操作页。

### 3.3 频谱页

独立整页，纵向瀑布图（新行在下、向上滚动）：

- **红线和频率刻度常驻**，即使还没收到第一帧也画（用设置里的频率范围作兜底轴），因此启动即可拖红线设发射频率。
- 顶部有奇偶色条；红线处一条半透明红条表示占用带宽。
- **解码报文叠加**：把最近若干时隙解出的报文按频率位置叠加在瀑布上，**竖排**文字（自上而下读），
  底端**锚在该信号的实际结束时刻**，随瀑布一起向上滚，滚出约 48 s 窗口（FT8 默认档约 3 个时隙）即消失。
  这条报文只读、不响应点击（防误触）。
- 频谱页**不显示**六个报文槽。

### 3.4 地图页

全屏深色底图（离线卫星影像，做了暗化）+ 实时标记：

- **底图**：Web Mercator 卫星栅格，与网格 / 呼号标记严格对齐；世界横向 + 纵向无缝循环；离线资源缺失时退回纯色世界矩形，地图页仍可用。
- **标记**：
  - **网格方块**：本会话累计解码到的网格 + 日志里已通联 / 已确认的网格；按**类别色**着色（见 [§4.4](#44-颜色说明)）。
  - **呼号点**：本会话累计 + 日志历史；有网格用网格坐标，没有则按呼号前缀归属地立点（带 `~`）。呼号文字在放大到一定级别后才出现。
  - **CQ 旗**：**只显示最近一个时隙**喊过 CQ 的台（旗杆 + 三角旗面），一个台站只画一处标记（喊过 CQ 的台不再画圆点）。旗面颜色表示**通联状态**：红＝从没通过 / 蓝＝只在别的波段通过 / 灰＝本波段已通过。
  - **信号连线**：只取**最近一个时隙**的报文；普通连线蓝色，**凡报文里提到我方的连线（线身 + 连线文字）标红**。
  - **昼夜灰线**：太阳明暗分界线，画在底图之上、所有标记之下，每 5 分钟刷新一次，不做开关。
- **端点定位优先级**：本条报文里的网格 > 本会话解码里收到过的网格 > 日志网格 > 呼号前缀归属地；「我」这一端一律用我方网格。
- **交互**：拖动平移、捏合缩放（最大可放大到很深）、右下角浮控（放大 / 缩小 / 回我的位置）；双击解码行可跳地图页并定位该呼号。
- **浮层**：图例 + 计数（网格 / 呼号 / CQ / 连线），底部一行操作提示。
- 三个显示开关（CQ 旗帜显示呼号 / CQ 旗帜显示强度 / 连线显示文字）在**设置页 → 地图**组里。

### 3.5 日志页

- 顶部**统计卡**：总通联、波段数、模式数、最近日期，另有一行记各波段的通联计数。
- 下面是通联记录卡片列表，可**搜索 / 筛选**、**编辑 / 删除**、**手动新增**。
- 每条记录含呼号、网格、收发报告、波段、起止时间与备注（`Distance: … km, QSO by Ft8Vox`）。
- ADIF 通过系统文件选择器（SAF）**合并导入 / 导出**，不需要存储权限。

### 3.6 设置页

分组：**台站 / 电台（仅 VOX）/ 音频 / FT8 / 高亮与提醒 / 日志 / 地图 / 关于**。
全部设置项与默认值见 [§7](#7-设置项一览)。

### 3.7 跟踪 CQ 列表

点控制行的「跟踪 N」打开：

- 标题栏：`⭐ 跟踪 CQ n` + `左滑呼叫 · 右滑取消跟踪` + 非空时的「全部清除」（二次确认）。
- **左滑＝呼叫**该台，**右滑＝取消跟踪**。
- 被自动收录的行带「自动」标记。
- 没有单独的关闭按钮；关弹窗走底部「关闭」/ 点外部 / 返回键。
- 名单**不是解码筛选**：它只影响自动程序是否呼叫 CQ 台，且名单里的台不受「自动跟踪 CQ」开关限制（见 [§6.10](#610-跟踪名单)）。

### 3.8 自动程序弹窗

从发射区「自动程序」按钮或设置页「FT8 → 自动程序」打开（同一套面板）。四项策略：

| 项 | 说明 |
| --- | --- |
| **发射监管** | `不监管` / `5 / 15 / … / 95` 分钟（默认 **10**）。连续发射超过该时长自动关闭发送总开关。 |
| **无回应次数** | `0`（默认，＝内置硬上限 20 个批次）/ `1…30`（超过 `2 × 该值` 批次即收尾换台）。 |
| **自动跟踪 CQ** | 开启时把本波段未通联的 CQ 台**记入跟踪名单**，并在其通联完成后移除；同时是「哪些 CQ 台可被自动呼叫」的闸门。 |
| **自动呼叫 CQ 台** | 总闸：是否真的去呼叫候选里的 CQ 台。关掉只回应定向呼叫 + 自己发 CQ。 |

> **自动程序没有独立开关**：打开「发送总开关」即启动自动发射，关闭即停。

| 解码行**双击** | 跳地图页并定位该呼号 |

## 4. 解码与显示

### 4.1 解码行

- **两行制，无表头**：
  - 第 1 行：`时隙 UTC 信号 dT 报文`（报文固定单行，放不下时逐级缩小字号，不再省略号截断）。
  - 第 2 行：`声音频率 国家 距离`，从行首开始，各项之间一个空格。
- **我方发射行（TX 行）**：`时隙 | TX | 报文`，**只占一行**、黄底，与接收解码行**按同一时间轴混排**；
  纯展示、不可点；被作废的那次在行尾标「未发完」。
- 新解码自动吸顶到最新；空态文案由纯函数 `decodeEmptyHint` 给出。
- 解码列表是「最近条数」的有界窗口（上限 200 条），旧条目自动淘汰。

### 4.2 整行底色与优先级

每行只有**一条色卡**（整行底色），取命中的**最高优先级**类别：

| 优先级（高→低） | 类别 | 底色 |
| --- | --- | --- |
| 1 | 正在发射 / **自己发的报文**（发方就是我方呼号） | 黄底黑字 |
| 2 | 与我有关 / 当前 QSO 对手 | 蓝 |
| 3 | CQ | 橙 |
| 4 | 已通联 | 红（报文列附加删除线） |
| 5 | 重复解码（同文本在更早时隙出现过） | 灰（整行变淡） |
| 6 | 新网格 | 紫 |
| 7 | 新 DXCC / ITU / CQ 区域 / 新前缀 | 棕 |
| 8 | 新呼号 | 粉 |
| 9 | 其余新解码（兜底） | 绿 |

「与我有关」＝报文**发给我的**（`addressedTo`，用复合呼号宽松匹配，兼容 `BG7ZJW/P`）。

### 4.3 报文列标红与文字修饰

- **发给我的报文**：**「报文」那一列整列标红**；同一行里「我的呼号」也用同一个红（只保留加粗）。
  其余各列（时隙 / UTC / SNR / dT / 频率 / 国家 / 距离）保持原色。**整行底色不受影响**。
- **已通联**：报文列红字 + 删除线。
- **重复解码**：整行降低透明度。
- **行尾小圆点**（恒开）：`与我有关` 画粉点、`当前通联对手` 画蓝点。

### 4.4 颜色说明

设置页「高亮与提醒」组里的图例是**颜色的唯一口径来源**（所有颜色恒启用，没有开关）。含义：

- **整行底色（色卡）**：按 [§4.2](#42-整行底色与优先级) 的优先级取一条。
- **报文列标红**：发给我的报文。
- **行尾小圆点**：粉＝报文里有我，蓝＝当前通联对手。
- **地图**：网格方块 / 呼号点用**类别色**（蓝＝本会话解码，黄＝已通联，红＝已确认）；
  信号连线蓝＝普通，红＝报文里有我；CQ 旗面用**通联状态色**（红 / 蓝 / 灰，见 [§3.4](#34-地图页)）。

## 5. 发射

### 5.1 发送总开关

- 是**唯一的发射闸门**（默认关＝只接收），始终显示在信息头第 1 行最右。
- 关闭时点击报文槽 / 发送只提示、不发射。
- **不持久化**：每次启动 App 都要手动打开。

### 5.2 六个报文槽

| 槽 | 类型 | 内容 | 点击动作 |
| --- | --- | --- | --- |
| 1 网格 | `GRID` | `目标 我 网格` | 发这一条 |
| 2 报告 | `REPORT` | `目标 我 报告` | 发这一条 |
| 3 R报告 | `ROGER` | `目标 我 R报告` | 发这一条 |
| 4 RR73 | `RR73` | `目标 我 RR73` | 发这一条 |
| 5 73 | `SEVENTY_THREE` | `目标 我 73` | 发这一条 |
| 6 CQ | `CQ` | `CQ <前缀> 我 网格` | 起 CQ |

- 槽内容每帧由六步序列现算，**不持久化**；报告值取**我方实测**，且**序号 2 与序号 3 用同一个值**（照 FT8CN）。
- **目标呼号**：通联进行中 / 有待发报文时以引擎的当前对手为准，空闲时才用点选目标（避免旧的点选呼号劫持组包）。
- 目标为空时槽 1–5 置灰。

### 5.3 自定义报文与 CQ 前缀

- **自定义报文**：在框里写一条 → 点「发送」→ 排到下一个（或最近可发的）我方时隙；QSO 进行中也照发（插一条、不打断原序列）；编不出来 / 被拒时底部红字当场说明；排程成功后框清空、QSO 继续。
- **CQ 前缀**：8 个可编辑格子（默认空 / `DX` / `ASIA` / `EU` / `NA` / `JA` / `TEST` / `POTA`）。
  前缀插在 `CQ` 与呼号之间（如 `CQ DX K1ABC FN42`），**空串＝普通 CQ**。选中项对**所有** CQ 生效（六槽 CQ、自动程序、手动呼叫）。

### 5.4 时隙、就地发射与换目标

- **时隙**：FT8 = 15 s / 时隙，FT4 = 7.5 s；奇偶两周期交替。选台时自动把发射对齐到对方的**相反周期**。
- **就地发射**：本时隙剩余时间够「报文波形 + 前导」播完就立即发，否则排下一周期
  （FT8 报文 12.64 s、FT4 5.04 s；判据用 `TxScheduler.minSendNowMs`）。
- **QSO 进行中必须等上一时隙的解码处理完再排定本时隙**，避免抢发旧报文、把新报文挤到下下周期。
- **发射途中换目标**：按同一判据当场**作废重发**。
- **前导**：无 CAT 时靠「PTT 延迟静音 + 发射前导音」让电台 VOX 抢先键控，再把数据对准时隙起点。
- **时隙偏移**：把**整个时隙**一起平移（解码窗口起点 + 发射起点），用于按解码 DT 校准本机时间 / 声卡时延；正值推后、负值提前。FT4 搜索窗窄，偏移过大会解不出。

### 5.5 同频 / 异频发射

设置页「FT8 → 同频发射」：

- **开（默认）＝同频发射**：选台时发射频率（红线）跟到对方频率，「点谁打谁」。
- **关＝异频发射（split）**：发射固定在红线位置，选台不改红线（红线只由用户拖动设置）。

## 6. QSO 自动系统

**一句话**：六步报文序号（`order` 1..6）＋ 单档常开自动程序 ＋ 两个安全阀（发射监管、无回应兜底）。

### 6.1 三层结构

| 层 | 职责 | 实现 |
| --- | --- | --- |
| 第 1 层 序号状态机 | 持有**一段** QSO 的全部状态；按「对方序号 + 1」推进六步；跑 5 路收尾判据；进入序号 4/5 即落库 | `qso/QsoEngine.kt` |
| 第 2 层 选台 / 调度 | 收集本批候选、决定「应答定向 / 换台 / 应答 CQ / 发 CQ」，跑发射监管；**不直接发射** | `qso/AutoProgram.kt` |
| 第 3 层 人工覆盖 | 手动呼叫 / 回复 / 查看日志；只改目标、复位监管，**不暂停**自动程序 | `ui/SessionViewModel.kt`、`ui/DecodeTable.kt` |

**关键约定**：

- **「一定应答」**：发给我的定向报文一律入选并优先处理，不受两个开关、显示筛选、已通联影响（只有显式`忽略呼号`会挡）。**只有 `73` 例外**（表示对方已收尾，不作为 QSO 起点）；指名给我的 `RR73`/`RRR`**要接**（我回 73 收尾）。
- **角色隐式**：主叫 / 应答者只供 UI，不驱动任何转移。
- **人工不暂停**：没有 `paused`；人工操作只是改目标 + 复位监管。
- **报文方向**：FT8 定向报文 = `<收方> <发方> <载荷>`，如 `K1ABC W2XYZ -08` 表示「发给 K1ABC、由 W2XYZ 发出」；我收到的报文里**我的呼号在第一位**。

### 6.2 六步报文序号

`order` ＝「**我下一条要发的报文序号**」：

| 序号 | 报文 | 含义 |
| --- | --- | --- |
| 1 | 网格 | 呼号 + 网格 |
| 2 | 报告 | 呼号 + 信号报告 |
| 3 | R 报告 | 呼号 + `R` + 信号报告 |
| 4 | RR73 | 呼号 + `RR73` |
| 5 | 73 | 呼号 + `73` |
| 6 | CQ | 主动呼叫 |

转移只有一条：**我下一条 = 对方这条的序号 + 1**。所有转移由报文载荷驱动，角色由序号动态推断。

### 6.3 序号判据

收到报文 → 判对方处于哪一步，判据照抄 FT8CN `checkFunOrder`：**先判 CQ，再按 6→5→4→3→2→1** 反查。

| 对方报文形态 | 判为序号 |
| --- | --- |
| `CQ …` | 6（对方在主叫） |
| `我 对方 73` | 5 |
| `我 对方 RR73` / `RRR` | 4 |
| `我 对方 R<报告>` | 3 |
| `我 对方 <报告>` | 2 |
| `我 对方 <网格>` | 1（**4 位与 6 位扩展网格都认**） |

### 6.4 推进与状态

- **推进**：收到对方序号 n → 我方下一条发 n + 1，直到进入收尾。
- **序号 4 之后不立即结束**：进入 `WAIT_FINAL`，**继续等对方 73**；等不到就每个周期重发 RR73。该状态**进入即落库**（双保险：进入序号 4/5 与「真正发出」各记一次，去重）。
- 状态机对外只暴露必要信息给 UI：当前对手、我方序号、收发报告快照、是否已放弃（换台）等。收发报告的「待发 / 已发出」按**真正播出**与否区分，不含糊。

### 6.5 报告值

- **我方发**：序号 2 的报告在**进入该步时按当时解码 SNR 算一次**并固定；**序号 3 的 R 报告复用序号 2 实际发出的同一个值**（照 FT8CN「定台时测到的强度」）。
  未推进的重复解码**不再刷新**报告值。
- **对方给**：命中一条就覆盖（序号 2 / 3 都会更新）。
- 报告范围 `−24 … +30 dB`。

### 6.6 无回应计数与 5 路收尾

- 无回应计数**按解码批次**累计；**空批不计**，弱信号不计；序号 6（CQ）阶段不计数。
- 收尾判据是 **5 路 OR**（在引擎里判定，第 2 层只负责换台 / 回 CQ）：
  1. 收到对方 `73`；
  2. 我方序号 5 后对方沉默（结构上我方已 `DONE`）；
  3. 我方序号 4、且 `无回应次数` 设为 `>0` 时，`无回应次数 > 2 × 该值`；
  4. 我方序号 4、对方转去呼别人；
  5. 我方序号 4、且 `无回应次数 == 0` 时，`无回应次数 > 20`（内置硬上限）。
- 命中后由第 2 层换台 / 回 CQ（有别的定向台就应答，有未通联 CQ 就应答首个，都没有就自己发 CQ）。

### 6.7 选台规则

- **候选来源**：对方的 `CQ`（S&P 应答）、**发给我的**定向报文（呼叫我 / 给我报告 / R 报告 / 直接给我 `RR73`）。
- **定向报文一律入选**，不受两个开关、显示筛选、已通联影响；只有显式「忽略该呼号」会挡。
- **CQ 台**：仅当「自动跟踪 CQ」开、**或**该台在跟踪名单里才入选；**本波段已通联的 CQ 台一律跳过**（跨波段通联过的台在本波段仍可入选）。
- **不做 DX / 区域分级**：候选保持解码先后，取第一台。
- **忙时目标沉默也会应答别人**：正在通联某台时，若本批里目标没有回应、而另有别人呼叫我方，则转而应答那个人（换台）；目标这一批有回应时不会被抢走。
- 两个开关都开、且存在未通联 CQ 候选时优先 S&P 应答第一台，否则自己发 CQ。

### 6.8 落库

- **落库时机**：进入序号 4 或 5 时即时落库。
- **字段**：呼号 / 网格 / 收发报告 / 波段 / 起止时间；`MY_CALL`/`MY_GRID` 取记录当时快照。
- **备注**：双方网格齐全时写 `Distance: 1738 km, QSO by Ft8Vox`（若设置里填了台站备注则为 `台站备注, Distance: …`）；任一方缺网格时只留 `QSO by Ft8Vox`。
- **去重**：同呼号在会话内只记一条（短时间内重复落库会忽略）。
- 落库后立即更新「已通联」索引（跨波段供高亮，当前波段供自动程序）。

### 6.9 防跑死

- **发射监管**：从开总开关（或人工操作）起连续发射超过设定时长，**自动关闭发送总开关**。
- **无回应兜底**：5 路 OR 收尾后换台或回 CQ（见 [§6.6](#66-无回应计数与-5-路收尾)）。
- **监管与入队**：自动程序的动作经队列串行下发，避免同一时隙重复排发射。
- **发射中止**：UI 线程「停止发射」走无锁的非阻塞中止，不会卡界面。

### 6.10 跟踪名单

- **内容** ＝ 设置里的 `followCalls`；来源两个：解码列表长按「跟踪」**手动**加入；「自动跟踪 CQ」开启时**自动**写入本波段未通联的 CQ 台（顺序记在 `autoFollowOrder`，最近在前）。
- **自动收录上限**：超 **100** 条时淘汰**最早收录**的；**手动跟踪的不占额度、永不淘汰**。
- **通联完成后自动移除**该台（**有意偏离 FT8CN**；对手动跟踪的台同样生效）。
- 「自动跟踪 CQ」关掉时**不再新增**，但已收录的台仍在名单里、仍会被自动呼叫，直到通联完成被移除或手动删。
- 名单里的台**不受**「自动跟踪 CQ」限制：照 FT8CN，它正是该开关的例外。

## 8. 与 FT8CN 的偏离清单

以下各处**有意与 FT8CN 不一致**，其余口径一律照 FT8CN：

1. **落库取引擎快照**：收发报告取「进入序号 4 那一刻」的值（FT8CN 落库前回查历史报文，两者通常一致）。
2. **复合呼号双向宽松**：`CallMatch.isFrom` 任一方带 `/` 即视为同一人，防对方改用 `/P` 时漏应答。
3. **无 2 秒时窗闸门**：逐条判定，晚到 / 大批量解码也能触发应答。
4. **逐条自听过滤**：只丢「落在我方发射那个时隙」的那一条解码，保留同批中对方的回复（不整批丢弃）。
5. **跟踪名单可从 App 内删除**：FT8CN 是独立表、只能在局域网 Web 后台删。
6. **6 位扩展网格也算序号 1**：FT8CN 只认 4 位，收到 6 位网格会解析不出序号而卡住。
7. **深度解码占位**：`DecodeResult.deep` 当前恒 `false`（native 单遍解码），仅预留「不驱动自动程序」的钩子。
8. **「自动跟踪 CQ」自动写跟踪名单**：FT8CN 的 `autoFollowCQ` 只把 CQ 推送到「呼叫」列表、不写名单；本机开启时把本波段未通联的 CQ 台写入 `followCalls`（超 100 条淘汰最早收录的，手动跟踪的不淘汰）。
9. **跟踪台通联完成后自动移除**：FT8CN 不会自动移除。

> 帮助文件里的原文引用「该呼号不会被长久保存到关注的呼号数据库中」照抄 FT8CN，未改字。

## 9. JNI 接口契约

Kotlin 与 native（`libft8.so`）之间的接口约定。

### 9.1 命名与符号

- Kotlin 入口类（均为 `object`，位于 `com.example.ft8vox.engine`）：`Ft8Engine`（离线解码 / 编码）、`AudioEngine`（实时音频 I/O 与时隙调度）。
- native 函数符号遵循 `Java_<包名下划线>_<类名>_<方法名>`。
- **重命名类或包时，必须同步修改 `app/src/main/cpp/jni_bridge.c` / `audio_engine.c`**。
- 这些 JNI 类 / 方法必须在 `app/src/main/keepRules/rules.keep` 中保留（防 release 混淆）。
- 解码核心（monitor + 呼号哈希 + 候选 / 解码）抽在 native 模块 `ftx_session.c`，离线（`jni_bridge.c`）与实时（`audio_engine.c`）共用。

### 9.2 数据格式

| 项 | 约定 |
| --- | --- |
| PCM 格式 | 单声道、`float32`、范围 `[-1.0, 1.0]` |
| 分析采样率 | **12 kHz** |
| 采集采样率 | 设备原生（常见 48 kHz），native 重采样到 12 kHz |
| 大数组传递 | `FloatArray`（`GetFloatArrayElements` 读取，块间无拷贝） |
| 文本编码 | UTF-8（报文为 ASCII 子集） |
| 协议 | `Protocol { FT8, FT4 }` |

### 9.3 生命周期接口（`Ft8Engine`，离线）

| 方法 | 职责 | 线程 |
| --- | --- | --- |
| `initialize(config: Ft8Config, decodeParams: DecodeParams = DecodeParams())` | 创建并初始化 monitor / waterfall，并下发解码参数 | 初始化线程 |
| `setDecodeParams(params)` | 更新**热生效**的解码参数 | 任意（内部无锁读写单字） |
| `reset()` | 清空当前时隙的 waterfall 与分块缓冲 | 解码线程 |
| `release()` | 释放 native 资源 | 与 initialize 同线程 |

`Ft8Config` 字段（对应 `monitor_config_t`）：`protocol`、`sampleRate`、`fMin`、`fMax`、`timeOsr`、`freqOsr`。
**改动 `Ft8Config` 需重建引擎**；`DecodeParams` 可在运行中调整。

### 9.4 解码接口

| 方法 | 职责 |
| --- | --- |
| `processAudio(samples, length)` | 接收任意长度的 12 kHz PCM；native 内按 monitor 块大小累积，余数留待下次（支持流式分块喂入） |
| `decodeDetailed(): List<DecodeResult>` | 时隙结束时调用，执行候选查找 + 解码，返回带指标的报文列表 |
| `decode(): List<String>` | 便捷方法，等价于 `decodeDetailed().map { it.text }` |

`DecodeResult` 字段（对应 `ftx_decode_result_t`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `text` | String | 解码出的报文明文 |
| `snr` | Int | 近似 SNR（dB，换算到 2500 Hz 参考带宽） |
| `dt` | Float | 相对时隙起点的**名义**时间偏移（秒），已减去 0.5 s 起始延迟 |
| `df` | Int | 音频频率偏移（Hz） |
| `score` | Int | 候选 Costas 同步得分 |
| `slotUtcMs` | Long | 所属时隙的 UTC 起点（毫秒）；离线解码为 0 |

> `DecodeResult` 由 native 直接 `NewObject` 构造，构造签名固定在 `jni_common.h`：
> `(Ljava/lang/String;IFIIJ)V`。**修改 Kotlin 字段顺序 / 类型时必须同步更新该签名。**

**SNR 口径**（照搬 JTDX / WSJT-X 同一尺度）：对每个符号取该符号实际发送音调所在 bin 的功率与本符号内其余音调 bin 的平均功率之比，在功率域对全部符号求平均后扣本底、按分析窗等效噪声带宽折算到 2500 Hz 参考带宽，最后钳位。

**可调解码参数（`DecodeParams` ↔ `ftx_decode_params_t`）**：

| 字段 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `minScore` | 10 | 4..40 | Costas 同步最低得分 |
| `maxCandidates` | 120 | 20..500 | 单时隙候选上限 |
| `ldpcIterations` | 20 | 5..60 | LDPC 最大迭代次数 |
| `maxDecoded` | 100 | 5..100 | 单时隙最多解出的报文条数 |
| `passes` | 2 | 1..4 | 多趟减谱重解（SIC）趟数；1 = 关闭 |

- 这些参数只影响搜索与 LDPC 迭代、不改变 STFT 结构，故可在接收过程中热更新；native 侧会再次钳制。
- `monitor_config_t`（`fMin`/`fMax`/`timeOsr`/`freqOsr`）不同：改动需重建引擎（重启接收）。
- **多趟减谱重解（SIC）**：解完一趟后，把已解出的报文重新编码出真实音调序列，逐符号只把该符号实际占用的那 1 个音调 bin 压平到本地最低幅度，得到残留谱后重搜重解，把被强台压住的同频弱信号挖出来。

### 9.5 编码接口

| 方法 | 职责 |
| --- | --- |
| `encode(text, frequencyHz, protocol, sampleRate): FloatArray` | 文本 → 77-bit 载荷 → tone → GFSK 波形，返回**一个完整时隙**的 12 kHz PCM（含首尾静音填充） |

- `protocol` / `sampleRate` 默认沿用最近一次 `initialize` 的配置。
- 报文无法解析 / 编码时抛 `IllegalArgumentException`。
- 时隙定位遵循 WSJT-X 约定：波形在时隙起点后 **0.5 s** 开始，末尾留白填满整个时隙。
- 覆盖报文：标准报文（CQ、呼叫、R/RR73/73）、自由文本；FT8 与 FT4。

### 9.6 实时音频接口（`AudioEngine`）

| 方法 | 职责 |
| --- | --- |
| `initialize(config, decodeParams)` | 创建实时引擎；重复调用先释放 |
| `setDecodeParams(params)` | 运行中热更新解码参数 |
| `release()` | 停止采集 / 播放并释放 |
| `startCapture(preferredRate = 48000, deviceId = 0): Int` | 打开采集流并启动 DSP 线程；返回设备实际采样率，负数为错误码 |
| `stopCapture()` | 停止采集并释放采集侧资源 |
| `pollDecoded(): List<DecodeResult>` | 取走并清空自上次调用以来解出的报文（拉取模型，无 native 回调） |
| `waterfallInfo(): WaterfallInfo?` | 频率轴：`bins`、`binHz`、`fMinHz` |
| `pollWaterfall(maxRows = 64): ByteArray` | 取走新产生的 waterfall 行（每行 `bins` 字节 uint8） |
| `startPlayback(preferredRate = 48000, deviceId = 0): Int` | 以阻塞写模式打开播放流；返回设备实际采样率，负数为错误码 |
| `stopPlayback()` | 关闭播放流（要等锁，**不要**在 UI 线程用它做「停止发射」） |
| `abortTx()` | 立即作废正在进行的发射写入（非阻塞、无锁，可在 UI 线程调用） |
| `play(pcm): Int` | 播放一个时隙的 12 kHz PCM，返回写入帧数 |
| `playTx(pcm, pttSilenceMs = 0, leadToneMs = 0): Int` | 发射播放：数据前插入静音与前导音，带看门狗写入 |
| `playTone(freqHz = 1000, durationMs = 2000): Int` | 播放测试单音 |
| `setVox(config)` | 下发 VOX / PTT 配置（热生效） |
| `setInputGain(gainDb)` | 下发采集增益（热生效，−12..30 dB） |
| `setOutputGain(gainDb)` | 下发输出音量（热生效，−30..0 dB） |
| `setSlotOffsetMs(offsetMs)` | 下发整时隙偏移（热生效，±2500 ms） |
| `state(): AudioState?` | 状态快照（运行 / 时隙进度 / 采样率 / 丢帧 / 已解码时隙数 / UTC / 输入电平） |
| `utcNowMs(): Long` | 当前 UTC 毫秒时间 |

**错误码**：`startCapture`：`-1` 未初始化、`-2` 无法创建 builder、`-3` 打开输入流失败、`-4` DSP 线程创建失败、`-5` 启动失败。
`startPlayback`：`-1` 未初始化、`-2` 无法创建 builder、`-3` 打开输出流失败、`-4` 启动失败。

**采集约定**：

- 请求 `preferredRate`（优先 48 kHz），native 重采样到 12 kHz：降采样先过 4 阶 Butterworth 低通再线性插值，升采样直接线性插值。
- 采集预设按 `UNPROCESSED → VOICE_RECOGNITION → GENERIC` 依次回退，尽量绕开系统降噪 / AGC（避免噪声底被压低、SNR 虚高）。
- 时隙调度按 UTC 对齐，仅在时隙起点后约 200 ms 内开始采集；边界判定用 `utc_now_ms() - slot_offset_ms`，上报的 `slot_start_ms` 仍是名义 UTC 时隙起点。
- 回调线程只写无锁 SPSC 环形缓冲，DSP 线程负责重采样与解码；缓冲满时丢弃样本并计数。
- waterfall 行每处理完一个 monitor block 写一行（FT8 约每 80 ms 一行）。

**发射时序（Kotlin 侧调度，不新增 native 线程）**：

1. 操作者打开总开关后先 `startPlayback()` 建好播放流，避免发射瞬间才建流而错过时隙；
2. 每约 80 ms 检查一次，计算目标发射时隙与播放起点；无前导时就地在「当前时隙奇偶 == 我方发射周期」且起点后 1200 ms 内发射；有前导时提前「PTT 延迟 + 前导音时长」启动，使数据仍落在时隙起点；同一时隙绝不重复写；
3. 迟到时按迟到量缩短前导以保持数据对齐，迟到超过「前导 + 1200 ms」则放弃本时隙；
4. **QSO 进行中必须等上一时隙的解码处理完再排定本时隙**；
5. 其余时间不向播放流写数据；紧急停止用 `abortTx()`。

**VOX / PTT（`VoxConfig`）**：`pttDelayMs`（默认 0，0–500）、`leadToneMs`（默认 0，0–2000）、`watchdogMs`（默认 10000，1000–60000）。
输入电平读数纯显示用，不做触发判定、不参与发射门控；看门狗以「本段音频预期播放时长 + 3 s」为实际阈值（不低于设定值），只在设备卡死时中止写循环。

**输出音量**：在写入声卡前对整段播放缓冲原地衰减（前导 / 报文 / 测试音一视同仁），只能衰减（波形本身已是数字满幅）。

### 9.7 线程模型

- **AAudio 回调线程**：只把 PCM 写入无锁 SPSC 环形缓冲，绝不调用重 JNI、加锁或分配内存。
- **DSP / 解码线程**：从环形缓冲取数据 → 重采样 → 按块累积 waterfall → 时隙结束解码，结果进入待轮询队列。
- **发射线程**：`encode` 生成 PCM，`play()` 内部重采样后阻塞写入 AAudio 播放流。
- **播放 / 关流的线程安全**：`playTx()` / `playTone()` 是阻塞写；`stopPlayback()` / 销毁引擎可能随时在另一线程执行。约定：
  - 分块写（`TX_WRITE_CHUNK_FRAMES` = 4096 帧，48 kHz 约 85 ms），每块之间释放锁并重查代次，避免整段发射独占锁导致 UI 线程 ANR；
  - 只在持有 `tx_mutex` 时访问 `out_stream`；
  - 用 `out_gen` 代次让退出的写入线程主动中止（主动中止不算失败）；
  - UI 线程「停止发射」走无锁 `abortTx()`（只加代次、不关流）；
  - 销毁引擎前确认没有播放调用在用引擎，否则宁可泄漏也不崩。

## 11. 已知限制

- **无 CAT**：频率 / 模式 / PTT 全靠人工与 VOX；操作页显示的频率只是本机设定，不代表电台实际状态。
- **单遍解码**：native 当前不输出弱信号二次解码，`DecodeResult.deep` 恒 `false`（自动程序对应钩子只是占位）。
- **SNR 只是近似**：口径照 JTDX，但本项目瀑布窗与之不同，强信号读数会被压缩（弱台基本无偏）。
- **DXCC 是前缀近似**：不做逐条精确实体判定。
- **地图无在线瓦片**：底图是打包的离线卫星影像（做了暗化），缩放很深时只是插值放大，不会更清晰。
- **呼号归属地是近似兜底**：台站没给网格时按其呼号前缀落点，用 `~` 标出。
- **亮色主题 / 字体档位不可用**：界面固定深色 + 固定字号（相关设置项已无 UI 入口）。
- **设置页偏卡**：切到 / 停留在设置页比其它页更卡。进入时要在主线程同步枚举音频设备（输入、输出各枚举两遍，共 4 次 `AudioManager.getDevices`）；该页又是全 App 最大的非惰性列表（`Column` + `verticalScroll`，非 `LazyColumn`），并同时订阅状态（约 5 Hz）、设置与全量日志。暂不优化。
