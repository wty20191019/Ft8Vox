# QSO 自动系统设计文档

## 系统架构分层

```
┌─────────────────────────────────────────────────────┐
│                    第3层：用户手动干预                │
│  用户设置呼叫目标 → 直接接管第1层，完成后恢复第2层    │
│  不修改第2层的调度状态，只是临时占用                  │
├─────────────────────────────────────────────────────┤
│                    第2层：自动程序调度                │
│  主叫模式 / 混合模式 → 决策何时发起何种QSO           │
│  负责选台、排队、调度第1层执行                       │
├─────────────────────────────────────────────────────┤
│                    第1层：QSO引擎                    │
│  对一个给定的目标呼号，执行一次完整的QSO交互          │
│  不关心目标怎么选的，只负责执行                      │
└─────────────────────────────────────────────────────┘
```

---

## 一、第1层：QSO引擎

### 1.1 职责

接收一个**目标呼号**和​**QSO类型**​（主叫/应答），执行一次完整的QSO交互，返回结果。

**​不负责：​**​ 选台、排队、排序、过滤重复通联。

### 1.2 输入/输出

| 项目 | 说明                                |
| ------ | ------------------------------------- |
| 输入 | 目标呼号 + QSO类型（主叫/应答）     |
| 输出 | 成功 / 失败（对方无回应达重试上限） |

### 1.3 主叫QSO流程

```
前提：上层已提供一个目标呼号（回应者）

① 发射时隙：发 对方呼号 + 信号报告
② 接收时隙：解码
   ├── 收到对方报告 → 进入③
   └── 无回应 → 重试计数+1，回到①
        └── 达 [3] 次 → 返回"失败"
③ 发射时隙：发 RR73
④ 接收时隙：解码
   ├── 收到对方 73 → 返回"成功"
   └── 无回应 → 重试计数+1，回到③
        └── 达 [3] 次 → 返回"失败"
⑤ 发射时隙：发 73（礼貌收尾）
```

### 1.4 应答QSO流程

```
前提：上层已提供一个目标呼号（CQ台）

① 发射时隙：发 对方呼号 + 信号报告
② 接收时隙：解码
   ├── 收到对方RR73 → 进入③
   └── 无回应 → 重试计数+1，回到①
        └── 达 [3] 次 → 返回"失败"
③ 发射时隙：发 73
④ 返回"成功"
```

### 1.5 重发机制

| 条件                        | 行为       |
| ----------------------------- | ------------ |
| 发出报告后对方无回应 [3] 次 | 返回"失败" |
| 发出RR73后对方无回应 [3] 次 | 返回"失败" |

### 1.6 发射时隙规则

整个QSO执行期间，发射时隙和接收时隙固定不变，只改变发射内容。

## 二、第2层：自动程序调度

### 2.1 职责

* 维护目标队列
* 选台、排序、过滤重复通联
* 调度第1层执行QSO
* 管理模式切换（混合模式的主叫/应答切换）

### 2.2 主叫模式调度

```
① 发CQ
② 解码周期结束，收集所有回应者
   ├── 无人回应 → 回到①
   └── 有人回应 →
        │
        应用选台规则过滤、排序，建立回应队列
        │
        取队首呼号，调用第1层 → 主叫QSO
        ├── 返回"成功" → 从队列移除该呼号
        ├── 返回"失败" → 从队列移除该呼号
        └── 队列非空 → 取下一位，继续调用第1层
             │
             └── 队列清空 → 回到①发CQ
```

### 2.3 混合模式调度

```
① 主叫状态
   │
   发CQ
   解码周期结束，收集所有回应者
   ├── 有人回应 →
   │    建立回应队列，逐个调用第1层主叫QSO
   │    队列清空 → 回到①
   │
   └── 无人回应 → 无人回应计数+1
        │
        └── 连续 [3] 次无人回应 →
               │
               ▼
② 应答状态
   │
   解码，扫描所有CQ台
   应用选台规则过滤、排序，建立CQ队列
   ├── 有CQ台 →
   │    取队首呼号，调用第1层 → 应答QSO
   │    ├── 返回"成功" → 立即回到①主叫状态
   │    └── 返回"失败" → 立即回到①主叫状态
   │
   └── 无CQ台 → 继续监听，不切回主叫
        │
        └── 出现CQ台 → 应答 → 回到①
```

### 2.4 选台规则（第2层使用）

| 规则                   | 行为                     |
| ------------------------ | -------------------------- |
| 允许重复通联（勾选）   | 不过滤已通呼号           |
| 允许重复通联（不勾选） | 从候选列表中剔除已通呼号 |
| 排序依据：解码先后     | 按解码到的时间顺序排序   |
| 排序依据：SNR优先      | 按信号强度降序排序       |
| 排序依据：距离优先     | 按距离降序排序           |

### 2.5 保护限制（第2层监控）

| 条件                         | 行为                        |
| ------------------------------ | ----------------------------- |
| 连续无有效QSO [10] 分钟      | 停止第2层调度，切回手动模式 |
| 单次发射总时长超过 [30] 分钟 | 停止第2层调度，切回手动模式 |

## 三、第3层：用户手动干预

### 3.1 职责

用户直接设置一个目标呼号，临时接管第1层，完成后恢复第2层。

### 3.2 流程

```
① 用户在解码列表中设置一个呼号为呼叫目标
② 暂停第2层调度（记住当前模式和状态）
③ 调用第1层 → 对该呼号执行QSO
   ├── QSO完成 → 恢复第2层调度
   └── 用户取消 → 恢复第2层调度
```

### 3.3 行为规则

| 用户操作        | 系统行为                    |
| ----------------- | ----------------------------- |
| 设置呼叫目标    | 暂停第2层，调用第1层执行QSO |
| 手动QSO进行中   | 第2层保持暂停               |
| 手动QSO完成     | 恢复第2层调度               |
| 手动QSO中途取消 | 立即恢复第2层调度           |

## 四、层间接口定义

```
第3层 → 第2层
  pause()
  resume()

第3层 → 第1层
  executeQso(call, type)   // 目标呼号 + QSO类型

第2层 → 第1层
  executeQso(call, type)   // 目标呼号 + QSO类型

第1层 → 第2层/第3层
  onResult(success/fail)
```

## 六、完整运行示例

### 示例：主叫模式，多人回应

```
第2层发CQ
解码到3人回应：JA1ABC, VK2DEF, W1XYZ
第2层应用选台规则 → 排序为 [JA1ABC, VK2DEF, W1XYZ]

第2层取 JA1ABC，调用第1层 → 主叫QSO
  第1层执行QSO → 返回"成功"
第2层从队列移除 JA1ABC

第2层取 VK2DEF，调用第1层 → 主叫QSO
  第1层执行QSO → 返回"失败"（对方无回应）
第2层从队列移除 VK2DEF

第2层取 W1XYZ，调用第1层 → 主叫QSO
  第1层执行QSO → 返回"成功"
第2层从队列移除 W1XYZ

队列清空 → 第2层继续发CQ
```

### 示例：混合模式，无人值守

```
第2层主叫状态 → 发CQ → 无人回应 × 3
第2层切换为应答状态

第2层解码到CQ台：JA1ABC
第2层取 JA1ABC，调用第1层 → 应答QSO
  第1层执行QSO → 返回"成功"
第2层立即切回主叫状态 → 发CQ
```

### 示例：用户手动干预

```
第2层正在主叫状态，发CQ
用户设置 JA1ABC 为呼叫目标
第3层暂停第2层
第3层调用第1层 → 对 JA1ABC 执行QSO
  第1层返回"成功"
第3层恢复第2层
第2层继续发CQ
```

## 七、隐式逻辑汇总

1. ​**第1层**​：只对一个目标执行QSO，不关心目标来源
2. ​**第1层**​：发射时隙和接收时隙固定不变
3. ​**第2层**​：负责选台、排序、过滤、排队
4. ​**第2层**​：混合模式应答完成后立即切回主叫
5. ​**第2层**​：混合模式应答无CQ台时保持监听
6. ​**第3层**​：手动干预优先级最高，临时占用第1层
7. ​**第3层**​：手动干预不修改第2层的调度状态

## 八、Ft8Vox 落地记录与偏离说明

> 本节由实现回填，非原始设计；实现位于 `qso/AutoProgram.kt`、`qso/QsoEngine.kt`、`ui/SessionViewModel.kt`。

- **模块映射**：第 1 层＝`QsoEngine`；第 2 层＝`AutoScheduler`（每个决策点返回 `AutoAction`，由 `SessionViewModel` 翻译成第 1 层调用）；第 3 层＝`SessionViewModel.manualIntervention()` / `resumeAutoAfterManual()`。
- **第 2 层实现方式**：纯 Kotlin、有状态（目标队列 / 当前阶段 / 主叫无回应计数 / 保护限制计时），不直接操作音频与状态机。发 CQ 后用 `QsoProgress.awaitingResponders` 标记，本时隙解码改交第 2 层 `collect()` + 排序决定应答对象（取代状态机自己认第一个回应者）。
- **模式取值**：`0 手动模式` / `1 主叫模式` / `2 混合模式`（本实现未保留旧「等级」概念）。
- **默认值**：`giveUpAfterRetry = true`、`retryLimit = 3`、`reportPriority = true`、`sortBy = SNR`、`allowRepeat = false`；保护限制两项**默认都不勾选**（文档 §2.5 的 □）。
- **收尾时序**：QSO 判成功时第 1 层通常还挂着最后一条 `RR73/73`，第 2 层要等这条发完才决定下一步（`pendingAutoFinish`），否则动作会覆盖状态机、丢掉收尾报文。
- **偏离 1（有意）**：**不采纳** §1.3 ④/⑤「主叫收到 `R报告` 后还要等对方 `73` 再发 `73`」。第 1 层保持标准 FT8 语义：收到 `R<报告>`/`RR73` 即判成功并发 `RR73`。原因：等待会让本已成功的 QSO 因对方不再回 `73` 而判失败。
- **偏离 2（等价）**：「解码时机」作为持久化设置项保留，但当前架构对整批解码结果统一处理，两个选项在实现上等价（见 `DecodeTiming` 注释）。
- **保护限制触发后**：停止第 2 层并切回 `0 手动模式`，**不动「发送总开关」**（总开关仍表示「允许发射」）。
