# Ft8Vox · 手机竖屏界面重设计（v2）

> 本文是「**放弃旧外壳，按手机触屏重做**」这一轮的设计准绳。
> 它**取代** `docs/UI-JTDX.md` 中「菜单栏 + 左侧竖导航 + 横屏外壳」那一整套形态；
> `docs/UI.md` 里的深色板、解码逻辑、JNI 契约、路线图、测试回归清单仍然有效。
>
> 决策来源：2026-09-29 与用户的**六轮问答**，逐条结论见 §1。
> 状态：**已落地**（见 §13），并已按实机反馈做过一轮微调（见 §14）。

## 1. 决策记录（六轮问答结论）

| 决策点 | 结论 |
| --- | --- |
| 设计基准 | **不照搬桌面**，按手机触屏习惯重做（控件大、层级浅、一屏一件事） |
| 屏幕方向 | **强制竖屏**（`sensorPortrait`） |
| 要治的病 | ① 操作路径太长 ② 太挤 / 装不下 |
| 核心场景 | 看解码列表 + 快速呼叫；看瀑布 + 调发射频率（两者并重） |
| 瀑布与解码 | **两个整页 Tab 切换**：操作页全屏解码，频谱页全屏瀑布 |
| 底部导航 | **5 项**：操作 / 频谱 / 地图 / 日志 / 设置，**图标 + 文字** |
| 解码行 | **单行表格 6 列**：时隙 / UTC / 分贝 / 时差 / 频率 / 信息 |
| 解码行高亮 | **照搬 JTDX 默认的「整行底色」**（色表见 §6） |
| 快速呼叫 | **保留左右滑手势**（左滑呼叫 / 右滑删除） |
| 六个报文槽 | **底部常驻**，竖屏放不下 → **3 列 × 2 行**，槽上**直接写报文内容** |
| 发射闸门 | **顶部一个总开关**（唯一闸门，默认关 = 只接收） |
| 顶部信息 | **四行紧凑**：频率+波段 / 时钟+时隙进度+电平+TX 徽标 / 呼号+网格+DX 目标 / 统计+时间同步+日期 |
| 频谱页 | 瀑布铺满 + 频率刻度 + 发射频率数字 + **可拖红线** + **把解码映射到频谱**（按频率位置标呼号文字、按类别上色、留最近 2–3 个时隙） |
| 频谱设频 | **拖动红线** |
| 状态条 | **取消底部状态条**（§26）：全部读数并进信息头第 4 行，去掉重复项 |
| 日志页 | **统计卡 + 卡片列表** |
| 设置页 | **单页长列表** |
| 地图页 | **保留世界网格图**，只重做外观与手势 |
| 配色 | **保留现有深色板 + 绿色高亮** |
| 主题 / 字号 | **亮/暗切换、字体档位都去掉**（只有暗色 + 固定字号） |
| 其余三页 | **一起重做** |

## 2. 屏幕骨架（竖屏）

```
┌──────────────────────────────────┐
│ 14.074 000    20m·FT8   [总开关 关]│ ① 信息头 第1行
│ 11:56:08  时隙 ▓▓▓░░ 1  [TX0]  -45dB ●│ ②      第2行
│ BG7ZZZ OM89            解码118ms  DX→JA1ABC PM95 -15│ ③      第3行
│ 解码12/min 总123 QSO7 队列0   时间同步 29.09.2026│ ④      第4行
├──────────────────────────────────┤
│ [监听] [清除] [关注 3]  时间同步 │ ⑤ 控制行
├──────────────────────────────────┤
│ 11:56:00  -12  0.1  CQ JA1ABC PM95 │ ⑥ 解码列表（两行制）
│ 1512 Hz  JA  1234 km              │ ⑦  （整行底色高亮）
│ …                                │   ← 主体，尽量多行
├──────────────────────────────────┤
│ [自定义报文__][CQ 无▾][发送]      │ ⑧ 发射区 第1行
│ [停止发射]            [自动程序]  │ ⑨        第2行
│ ┌网格───┐┌R报告──┐┌ 73 ───┐      │ ⑩ 报文槽 3列×2行
│ ┌报告───┐┌RR73───┐┌ CQ ───┐      │ ⑪  列优先 1 3 5 / 2 4 6
├──────────────────────────────────┤
│  ▭操作  ▭频谱  ▭地图  ▭日志  ▭设置│ ⑫ 底部导航
└──────────────────────────────────┘
```

固定高度合计约 **360dp**，普通竖屏手机（可用 ~750dp）留给解码列表 **约 390dp ≈ 19 行**，
彻底解决上一版「解码列表被挤成 0 高度」的问题。

> **底栏已取消**（§26）：原「细状态条」整条搬到信息头**第 4 行**，并去掉与上三行重复的
> 「模式 / 时隙 / 接收·发射文字」。底部导航（⑫）现在是整个界面的最后一行。

## 3. 操作页

### 3.1 信息头（四行，全局常驻）

| 行 | 左 | 中 | 右 |
| --- | --- | --- | --- |
| 1 | 大频率 `14.074 000` + `20m·FT8` | — | **发送总开关**（方块，开=绿底） |
| 2 | `11:56:08` | 时隙进度条 + `时隙 1` | 输入电平 + **`TX0/TX1`** + 接收状态点 |
| 3 | 我方 `BG7ZZZ OM89` | `解码 118ms` | `DX→JA1ABC PM95 -15` |
| 4 | `解码12/min 总123 QSO7 队列0` | — | `时间同步`（或红字 `时间不同步`）+ `29.09.2026` |

- 频率 = `status.dialHz`；波段/模式 = `status.band` / `status.protocol`。
- 时钟 = `QsoTime.isoTime(nowMs)`；时隙进度 = `slotProgress × slotMs`。
- DX 目标 = 当前 `qso.theirCall` / 最近一条该台解码的网格 / `reportSent`；
  没目标但正在叫 CQ 时显示 `CQ 呼叫中，暂无目标`（`dxTargetLabel()`）。
- 未设置呼号时整行第 3 行变红：`请先到设置填写呼号与网格`。
- **发送总开关**放第 1 行最右，始终可见；关=「只接收」，开=「允许发射」。
- **第 4 行 = 原底部细状态条**（§26）：解码速率 / 解码总数 / 通联数 / 队列长度 / 时间同步 / 日期。
  与上三行重复的三项（模式、`时隙 N`、`接收/发射` 文字块）已去掉，不再各显示一遍。

### 3.2 控制行（一行）

`[监听]`（接收中显示 `监听 ▣`）`[清除]` `[关注 N]`（弹窗：关注列表），右侧小字为时间同步提示。

**不做筛选、不做搜索**（§20 起）：解码列表永远显示全部解码（只受忽略名单与「已通联/重复」这类固定呈现影响）。

### 3.3 解码列表

- **两行制**（§13 起）：第 1 行 `时隙 UTC 信号 dT 报文`，第 2 行 `声音频率 国家 距离`；无表头。
- **整行底色高亮**，颜色取命中类别的最高优先级（§6）。
- **报文的额外标红**（§29）：发给我的报文，**「报文」那一列整列标红**；已通联的报文列是**红字 + 删除线**。
  两者都不动整行底色（色卡规则照旧）。
- 行高 ~2 行，新解码自动吸顶（沿用现有 `followNewest` 逻辑）。
- 空态文案沿用纯函数 `decodeEmptyHint`（已有单测，不要改名）。

### 3.4 发射区（底部）

- 第 ⑦ 行：`[自定义报文 ______]` `[CQ 前缀 无 ▾]` `[发送]`（自定义为空则置灰）。
  **框平时保持空白**，灰字占位回显**当前待发报文**（=「待发」的唯一文字读数；另有第 ⑨ 行
  「正在发送 / 空闲」与六格槽的绿点）；**没有「生成信息」键**（§28：点下面六格就是六步标准报文）。
  在框里写一条 → 点「发送」→ 排到下一个（或最近可发的）我方时隙（**QSO 进行中也照发，只是插一条、
  不打断原序列**）；编不出来 / 被拒时底部红字当场说明；**排程成功后框清空、QSO 继续**。
- 第 ⑦ 行的 `[CQ 前缀 ▾]` 打开 **CQ 前缀弹窗**（§28）：8 个格子可改、点一行即选中该格，见 §28.3。
- 第 ⑧ 行：`[停止发射]`（红，仅在发射中可用）`[自动程序]`（弹窗）`正在发送：<报文>` ——
  发射中**红字**显示本时隙实际在播的那条（`lastTxText`），空闲时**灰字**显示「空闲」。
- 第 ⑨⑩ 行：**六个报文槽 3 列 × 2 行、列优先**，槽上直接写报文内容（两行文本可换行，不再截断）：

  ```
  1 网格    3 R报告    5 73
  2 报告    4 RR73     6 CQ
  ```

  槽号就是六步序列的序号（槽号不变、只是排布改成列优先），**点哪一格就发那一格的报文**。

| 槽 | `TxMessageKind` | 内容 | 点击 |
| --- | --- | --- | --- |
| 1 网格 | `GRID` | `目标 我 网格` | `sendOnce` |
| 2 报告 | `REPORT` | `目标 我 报告` | `sendOnce` |
| 3 R报告 | `ROGER` | `目标 我 R报告` | `sendOnce` |
| 4 RR73 | `RR73` | `目标 我 RR73` | `sendOnce` |
| 5 73 | `SEVENTY_THREE` | `目标 我 73` | `sendOnce` |
| 6 CQ | `CQ` | `CQ <前缀> 我 网格` | `startCq` |

- 槽内容**不持久化**，每帧由 `TxCompose.compose` 现算，永远与六步序列一致。
- 目标为空时 Tx1–Tx5 置灰；指示灯按格独立（§25）：**正在播的那格红点红边、待发那格绿点绿边**。
- 第 ⑨⑩ 行下面的一行提示（§27）：一次性发射被拒 / 编不出来的**原因（红）** 优先，
  其次是常驻的「只接收：…」（红），最后才是 QSO 进度（绿）。
- 闸门仍是**发送总开关**；关闭时点击由 `SessionViewModel` 拦下并提示，不弹确认框。

## 4. 频谱页

```
┌──────────────────────────────────┐
│ （全局信息头四行，§26）            │
├──────────────────────────────────┤
│ 发射频率 1234 Hz     20m·FT8      │ 频率读数（随红线走）
├──────────────────────────────────┤
│                                  │
│        瀑  布  铺  满             │ ① 瀑布本体
│   CQ JA1ABC  ▏  BG7ZZZ   ▏       │ ② 解码文字叠加（按频率位置）
│ ────────────────────────────     │ ③ 横轴频率刻度（kHz）
│      ▲红线 = 发射频率（可拖动）   │ ④
├──────────────────────────────────┤
│  ▭操作  ▭频谱  ▭地图 ▭日志 ▭设置  │
└──────────────────────────────────┘
```

- **瀑布铺满**内容区；横轴是音频频率刻度（`0 … 3000 Hz`，按 `decode.fMaxHz` 自适应）。
- **基线常驻**（§23）：频率**网格 + 刻度小字 + 发射红线**不依赖瀑布数据，一进页面就画出来；
  还没有第一帧时（`frame == null`）用 `decode.fMinHz`–`decode.fMaxHz` 当频率轴，启动瞬间不再一片黑。
- **可拖红线** = 发射频率（报文**下边频**）；水平拖动红线设频，读数实时更新并持久化。
- **解码映射到频谱**：在每条解码的 `df` 位置标出**呼号文字**，颜色用该条的 JTDX 类别色（§6），
  只保留**最近 2–3 个时隙**，过期自动淡出/消失，避免糊屏。
- 文字为**只读展示**（本轮不做「点频谱文字直接呼叫」，避免误触）。
- 频谱页**不显示底部六个报文槽**（让瀑布尽量大）；要发射切回操作页。
- 右下角保留 `TX xxxx Hz` 读数 + 贴底时隙进度条（沿用现有实现）。

## 6. 解码行高亮（照搬 JTDX / WSJT-X 默认）

数据来源：WSJT-X `DecodeHighlightingModel::defaults_`（JTDX 继承同一套默认）。
**形式一律是「整行底色」**（深色板上会按 ~35% 不透明度铺底，保证文字仍清晰可读）。

| 类别 | 默认底色 | 本项目 |
| --- | --- | --- |
| 自己发的（Transmitted） | 黄 `#FFFF00` | ✔ 恒开 |
| 叫我（My Call in message） | 红 `#FF6666` | ✔ 恒开 |
| CQ in message | 绿 `#66FF66` | ✔ 恒开 |
| 新 DXCC / 本波段新 DXCC | 品红 `#FF00FF` / `#FFAAFF` | ✔ 恒开 |
| 新网格 / 本波段新网格 | 橙 `#FF8000` / `#FFCC99` | ✔ 恒开 |
| 新呼号 / 本波段新呼号 | 青 `#00FFFF` / `#99FFFF` | ✔ 恒开 |
| 新大陆 / 本波段 | `#FF0063` / `#FF99C2` | 归入新 DXCC 底色 |
| 新 CQ 区 / 本波段 | `#FFBF00` / `#FFE499` | 归入新 DXCC 底色 |
| 新 ITU 区 / 本波段 | `#A6FF00` / `#DDFF99` | 归入新 DXCC 底色 |
| LoTW 用户 | 前景 `#990000` | 未做 |

**优先级**（命中多个时取最高）：

1. **自己发的 / 正在发射**（本应用会把「自己发的解码行」显示在列表里，所以提到最高，保证黄底）
2. 叫我 / 当前通联对手（红）
3. CQ（绿）
4. 已通联（**不上底色**，红字 + 删除线）
5. 重复（**不上底色**，整体降透明度）
6. 新网格（橙）
7. 新 DXCC（品红；新 ITU 区 / 新 CQ 区 / 新前缀 与它同档）
8. 新呼号（青）
9. 其余（无底色）

> 本应用的「新前缀」归入「新 DXCC」同一底色；「已通联 / 重复」沿用弱化表达
> （JTDX 里 worked-before 也是弱化而不是另给一种颜色）。
>
> **这些高亮全部恒开**（docs/UI-MOBILE.md §29 取消了逐个开关）。另外「发给我的报文」会把
> **报文那一列的文字标红**，见 §29。

## 7. 底部导航

5 项 `图标 + 文字`，选中项绿色。图标取自 `material-icons-core`（本项目无扩展图标库）：

| 页 | 图标 |
| --- | --- |
| 操作 | `Icons.AutoMirrored.Filled.List` |
| 频谱 | **自绘**：4 条横向瀑布色带（蓝→青→绿→黄）+ 一条红色发射线 |
| 地图 | `Icons.Filled.Place` |
| 日志 | `Icons.Filled.DateRange` |
| 设置 | `Icons.Filled.Settings` |

> core 里没有「瀑布」图标，频谱一项用 `Canvas` 自绘（见 §14）；其余用 Material 图标。

**统计读数**（§26 起移入信息头第 4 行，底部不再有独立状态条）：
`解码12/min · 总123 · QSO7 · 队列1` 居左，`时间同步（或红字警告）· 日期` 居右。

`[TX0]` / `[TX1]` 是**我方发射时隙**（§21）；轮到我方或正在发射时红底黑字，其余深灰底灰字，
放在信息头第 2 行「时隙 N」右侧（§26）。

## 8. 交互与手势

| 操作 | 行为 |
| --- | --- |
| 解码行**单击** | 设为目标 + 对频 |
| 解码行**双击** | 跳地图页并定位该呼号 |
| 解码行**长按** | 菜单：呼叫 / 回复 / 详情 / 日志 / 复制 / 关注 |
| 解码行**左滑** | 设为目标并呼叫（绿条提示） |
| 解码行**右滑** | 删除该条（灰条提示） |
| 频谱**拖动红线** | 设发射频率（读数实时更新、重启保留） |
| 报文槽**点击** | 立即排程发射（CQ 槽走 `startCq`） |
| 发送总开关 | 唯一发射闸门；关=只接收，点击槽/发送只提示不发射 |
| 「关注 N」 | 关注列表弹窗（左滑呼叫 / 右滑取消关注 / 右上「全部清除」） |

## 27. 实机第十四轮：自定义报文要能发出去（2026-09-29，已完成）

### 27.1 原来为什么发不出去（先把控制逻辑理清）

链路：`自定义报文框` → `发送` → `SessionViewModel.sendOnce` → `sendOnceInternal` → `txTick`。

```
sendOnceInternal（改前）
  ├─ !canOperate          → 只写 status「请先填写呼号」           ← ①
  ├─ !txEnabled           → 只写 status「请先打开「发射」开关」    ← ①
  ├─ qso.active           → 只写 status「QSO 进行中，暂不逐条发送」← ②
  └─ manualTxText = 文本, txArmed = true  →  txTick: manualTxText ?: qso.txText
```

| 问题 | 说明 |
| --- | --- |
| ① **提示没有显示位置** | 这三条拒绝都只写进 `ReceiverStatus.status` 字符串，而竖屏外壳里**没有任何地方显示它** —— 点「发送」看上去什么都没发生。 |
| ② **`qso.active` 直接拒绝** | 自动程序常开 + 总开关打开时，`qso.active` 基本长期为真（自动叫 CQ 后 `awaitingResponders`、自动应答都是 active），于是**最想手动发一条的时候恰好发不出去**。而且「QSO 进行中不允许」的理由（避免打断自动序列）其实**不成立**：`manualTxText` 本来就只是插一条，`manualInFlight` 发完**不推进状态机**。 |
| ③ **手打的字会被自动覆盖（真 bug）** | `customEdited` 这个「手动改过」标记**从来没有被置成 true**（只有 `= false`），而 `LaunchedEffect(pending) { if (!customEdited) custom = pending }` 会在待发报文一变时覆盖输入框 —— QSO / 自动程序在跑时 `pending` 每个时隙都变，**刚打的字下一拍就没**。空闲时 `pending` 恒为 null 不变，所以「有时能打字」。 |
| ④ **非法报文提示太晚** | FT8 编不出来的文本要到**发射时隙编码时**才抛 `无法编码报文`，白等一个周期。 |

### 27.2 改法（本轮）

| 反馈 | 处理 |
| --- | --- |
| 自定义报文要能发出去 | **① 提示可见**：`ReceiverStatus` 新增 `txNotice`（红字，`TX_NOTICE_MS=6s` 后自动消失），发射区底部那一行改为按优先级显示：**一次性发射被拒原因（红）→ 常驻「只接收：…」（红）→ QSO 进度（绿）**。拒绝理由由纯函数 `txBlockReason(myCall, txEnabled)` 统一给出（没填呼号 / 只接收），`armPlayback` / 音频未启动失败也走它。 |
| | **② 放开 `qso.active`**：QSO 进行中**允许**发自定义报文 = **插一条、不打断**（用户确认的语义）。`txTick` 里 `manualTxText` 优先级本就高于 `qso.txText`，发完 `manualInFlight` 分支不推进状态机；**新增保持武装**：`txArmed = qsoStillNeedsTx(p) && txEnabled` —— 否则那条分支原本会把 `txArmed` 清成 `false`，把正在跑的 QSO **悄悄掐断**（改前 `qso.active` 被拒绝，所以这个坑没暴露出来）。 |
| | **③ 修 `customEdited`**：输入框 `onValueChange` 里 `customEdited = it.isNotBlank()`（清空输入框即回到自动同步）；发送**成功后**（`status.manualTxText` 正是框里这条）交回自动同步，失败则保留手打的字让人改。 |
| | **④ 前置校验**：`sendOnce` 先在**后台线程**试编码一次（`canEncodeMessage`，`nativeEncode` native 侧无状态、任意线程可调），编不出来就红字「FT8 编不出这条报文：<文本>」并**不排程**。 |
| 其它 | `docs/UI-MOBILE.md` §3.4 同步（自定义报文行 / 槽指示灯 / 底部提示一行）；新增单测 `TxSendGateTest`（8 例：`txBlockReason` 4 + `qsoStillNeedsTx` 4，共用纯逻辑）。 |

**语义澄清（本轮定稿）**：自定义报文 = **手动一次性报文插一条**。
- 空闲时发：排到下一个我方时隙，发完即解除武装。
- QSO 进行中发：同样排到下一个我方时隙、**优先级高于 QSO 的待发报文**；发完**不推进状态机**，QSO 接着发（对方可能因此多等一个周期，这是手动优先的代价）。
- 在 `txTick` 的「等本批解码」闸门（`qso.active` 时本时隙该发什么取决于上一时隙解码）上**不特殊化处理**：手动报文与 QSO 报文走同一条路径，只是顺序上优先、不改变时序。
- 点「发送」按钮**不置灰**（灰了就看不出为什么不能发）：能发就排程，不能发就当场红字说明。
